# Visual Agent Copilot 与 Technical Visual Companion 设计

## 1. 背景与目标

`role-copilot-skills` 按企业角色组织可安装、可复用的 workflow skills。现有一级角色容器包括 DevOps、Project 和 HR。本设计新增视觉表达角色容器 `visual-agent-copilot`，负责把复杂内容转化为易理解、可交付的视觉表达。

首个具体 skill 为 `technical-visual-companion`。它将已经确认的技术方案转化为高质量、单文件、离线可查看的 Visual Companion HTML。

第一版只解决一个问题：

> 用户提供已确认的技术方案后，自动选择最合适的 1～3 种技术图形，生成具有统一设计语言但不机械套版的静态 HTML，并在交付前完成确定性检查和桌面/移动端视觉验收。

## 2. 已确认决策

- 一级角色容器：`visual-agent-copilot`。
- 首个 skill：`technical-visual-companion`。
- 直接加入现有 `role-copilot-skills` 仓库。
- 只接受已经确认的技术方案，不负责需求澄清或方案补全。
- 输入来自当前对话中的已确认内容，或用户明确指定的本地文件。
- 不自动扫描整个仓库。
- 自动选择 1～3 张最有信息价值的图。
- 采用统一的 Superpowers 技术视觉语言，但根据内容调整构图和语义色。
- 第一版只交付一个静态 HTML。
- 默认输出到 `docs/visuals/<topic-slug>.html`，用户指定路径时优先使用用户路径。
- 最终 HTML 不使用 JavaScript、iframe、CDN、外部字体或网络请求。
- 必须同时通过文件检查和桌面/手机浏览器视觉验收。

## 3. 仓库结构

```text
role-copilot-skills/
├── devops-agent-copilot/
├── project-agent-copilot/
├── hr-agent-copilot/
└── visual-agent-copilot/
    ├── README.md
    ├── README.zh.md
    └── technical-visual-companion/
        ├── SKILL.md
        ├── references/
        │   ├── diagram-selection.md
        │   ├── visual-language.md
        │   └── html-contract.md
        ├── scripts/
        │   └── validate_html.py
        └── evals/
            └── evals.json
```

`visual-agent-copilot` 是角色容器，不承担具体生成逻辑。每个子 skill 解决一个重复出现的视觉工作流。

## 4. 触发边界

### 4.1 应触发

- 把已确认技术方案做成一张或几张图。
- 把架构、部署流程、调用时序或状态变化生成静态 HTML。
- 把设计文档转成类似 Superpowers Visual Companion 的视觉页面。
- 把多个互补技术视图放进一个离线 HTML。

### 4.2 不应触发

- 方案仍在讨论，需要继续梳理需求。
- 用户要求实现真实业务网页、管理后台或产品 UI。
- 用户只需要 Mermaid、PNG、PPT 或 PDF。
- 用户要求修改 Java、Docker Compose 或部署代码。
- 用户只想阅读、总结或评审文档。

## 5. 输入与输出契约

### 5.1 输入

允许读取：

- 当前对话中已经明确确认的内容。
- 用户明确指定的 Markdown、README、现有 HTML、代码片段或其他本地文本文件。

禁止：

- 自动扫描未授权目录。
- 自行选择历史版本或旧设计作为事实来源。
- 把推测、建议或未选方案画成既定事实。

### 5.2 输出

第一版只输出一个 HTML：

```text
docs/visuals/<topic-slug>.html
```

用户指定路径时使用用户路径。默认不覆盖已有文件；目标存在时先请求确认或使用新的文件名。

页面语言跟随输入材料，中文方案默认生成中文页面。中间分析、浏览器预览和检查可以使用临时文件，但不作为用户交付物。

## 6. 内部组件

### 6.1 SKILL.md

- 判断触发条件。
- 检查输入是否已经确认。
- 提炼视觉事实模型。
- 选择图形并控制生成流程。
- 执行文件检查和浏览器验收。
- 只在全部门禁通过后返回最终路径。

### 6.2 diagram-selection.md

提供关系到图形的选择规则：

| 技术关系 | 推荐表达 |
|---|---|
| 系统边界、职责、上下游 | 系统边界图、职责图 |
| 服务调用、同步异步交互 | 时序图、泳道图 |
| 状态变化、重试、失败恢复 | 状态机 |
| 部署节点、网络、端口、容器 | 部署拓扑图 |
| 数据来源、处理和去向 | 数据流或管线图 |
| 多方案、版本或能力差异 | 对比矩阵 |
| 分阶段执行、发布过程 | 阶段流或时间轴 |

Skill 选择最有信息价值的 1～3 张图，不要求覆盖所有关系。如果一张图足够，就只生成一张。

### 6.3 visual-language.md

固化设计语言而不是固定页面模板：

- 明亮、清晰的技术视觉。
- 圆角技术面板、细网格、柔和阴影和明确箭头。
- 处理中、成功、等待、失败使用稳定语义色。
- 通过位置、连线、泳道和状态节点表达关系，避免卡片堆叠。
- 桌面端展示完整横向关系，移动端转换为纵向流程。
- 图表构图随内容变化，避免不同方案生成完全相同的页面。

### 6.4 html-contract.md

- 一个 doctype 和一个 HTML 根节点。
- UTF-8、无 BOM。
- HTML、CSS、SVG 全部内嵌。
- 无 JavaScript、iframe、CDN、外部字体和网络请求。
- SVG 包含可访问性标题和说明。
- 支持 320px 及以上宽度。
- 支持系统深色主题，但默认保持明亮技术风格。
- `prefers-reduced-motion` 下关闭非必要动画。

### 6.5 validate_html.py

确定性检查包括：

- 文件可按严格 UTF-8 解码且无 BOM。
- HTML 基本结构唯一。
- 不存在脚本、iframe 和外部资源。
- section、标题和 SVG 可访问性符合要求。
- 存在窄屏响应式规则和 reduced-motion 规则。
- 文件大小处于合理范围。
- 用户要求保留的关键名称、数量和版本仍然存在。

该脚本只验证可确定的事实，不代替浏览器视觉评审。

## 7. 生成流程

```text
确认输入来源
  → 建立视觉事实模型
  → 自动选择 1～3 种图
  → 规划页面信息层级
  → 生成静态 HTML
  → 运行 validate_html.py
  → 桌面宽度浏览器验收
  → 手机宽度浏览器验收
  → 修正并重新验证
  → 返回最终 HTML 路径
```

视觉事实模型至少包含：主题、参与者、系统边界、组件职责、连接关系、执行顺序、状态转换、成功条件、失败回滚、禁止触碰范围，以及必须保留的名称、数量和版本。

## 8. 页面信息结构

```text
紧凑标题区
├── 主题
├── 一句话核心结论
├── 本次可视化范围
└── 多图时的锚点导航

图 1～3
├── 图标题
├── 本图回答的问题
├── 主视觉
├── 必要图例
└── 一条关键边界或风险提示
```

不把完整设计文档搬入页面，不用 KPI 卡片填充空白，不重复呈现同一关系。只有颜色具有稳定语义时才添加图例。

## 9. 内容忠实度与停止门禁

- 名称、接口、状态和版本保持原文。
- 不为构图整齐而合并业务上不同的对象。
- 不把可能、建议或计划画成事实。
- 数量关系必须准确。
- 用户明确指定图表类型或数量时，优先服从用户要求。

遇到以下情况停止生成：

1. 输入仍包含未选择的方案。
2. 不同来源对同一关系描述冲突。
3. 缺少所需图形的关键顺序或状态信息。
4. 目标文件存在且未授权覆盖。
5. 只能扫描未指定目录才能补齐信息。
6. 方案包含敏感内容，但用户没有明确要求写入 HTML。

停止时只说明缺口、影响和需要确认的内容，不先生成不准确草稿。

## 10. 完成标准

只有同时满足以下条件才可交付：

- 文件契约检查通过。
- 桌面宽度无横向溢出、裁切和文字遮挡。
- 320～390px 手机宽度可完整阅读。
- 每张图都回答一个明确问题。
- 页面不存在业务事实漂移。
- 浏览器无错误或资源加载失败。
- 最终目录只新增一个用户需要的 HTML。

## 11. 测试与评估

第一轮至少包含三个测试场景：

1. 复杂方案：包含系统边界、时序、状态和回滚，期望生成 2～3 张互补图。
2. 简单方案：只包含组件关系和步骤，期望只生成 1～2 张图，不强行扩充。
3. 冲突方案：存在未确认选择或来源冲突，期望停止且不生成 HTML。

自动评估文件契约、关键事实保留和输出位置。浏览器评估桌面/移动端布局。人工评估图形选择、可理解性、视觉品质和模板化程度。

第一次评估同时运行有 Skill 和无 Skill 两组输出，由用户进行并排评价；自动分数不能替代视觉人工评审。

## 12. 第一版非目标

- 不输出 PNG、PDF、PPT 或 Mermaid。
- 不生成交互式 JavaScript 页面。
- 不提供固定 HTML 页面模板。
- 不负责讨论、修订或补全技术方案。
- 不修改输入文档或业务代码。
- 不自动提交 Git 或发布网站。
- 不承担普通前端页面、产品 UI 或管理后台设计。

## 13. 后续扩展

第一版稳定后，`visual-agent-copilot` 可以增加独立兄弟 skills：

```text
visual-agent-copilot/
├── technical-visual-companion/
├── data-storytelling-copilot/
├── presentation-visual-copilot/
├── document-diagram-copilot/
└── interactive-explainer-copilot/
```

这些能力保持独立，避免 `technical-visual-companion` 膨胀成万能网页生成器。
