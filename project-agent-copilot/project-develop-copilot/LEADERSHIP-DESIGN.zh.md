# Project Develop Copilot 简版设计

## 一句话定位

Project Develop Copilot 是一个项目研发生命周期助手，让 AI 不再只处理单次编码任务，而是围绕同一个需求或问题，持续管理上下文、范围、执行、验证、交付和知识沉淀。

![Project Develop Copilot 领导层概览](./assets/project-develop-copilot-leadership.png)

## 为什么需要

真实项目开发中，AI 最大的风险不是不会写代码，而是容易丢上下文、扩大范围、忽略历史决策、跳过验证，或者把一次性回答当成项目事实。

Project Develop Copilot 的目标是把这些风险收拢到一个可控流程里：

- 让需求、Bug、临时资料和历史上下文有统一入口。
- 让每次开发都有明确 scope，不默认拉全仓库。
- 让验证、交付和知识回写成为闭环。
- 让项目经验沉淀到 `.llm-wiki`，下次可以恢复。
- 让 review 不只看代码，也能发现流程、上下文和 skill 规则问题。

## 核心能力

| 能力 | 说明 |
|---|---|
| 识别意图 | 判断用户是在查询、导入资料、开发需求、修 Bug、收尾还是 review。 |
| 恢复上下文 | 从 `.llm-wiki`、需求、Bug、工作上下文和项目日志中恢复当前状态。 |
| 限定范围 | 区分 active、reference-only、candidate、excluded 模块，减少范围漂移。 |
| 编排执行 | 在项目上下文准备好后，再桥接计划、调试、实现、验证等能力。 |
| 回写知识 | 将验证后的结论、变更、风险和缺口同步回项目知识层。 |

## 生命周期闭环

```text
Init 初始化项目上下文
  -> Ingest 导入资料
  -> Develop / Fix 开发或修复
  -> Finish 验证与交付
  -> Review 风险检查与持续改进
  -> 回到项目知识库和下一轮开发
```

这个闭环强调三件事：

- 每个入口都可恢复。
- 每个入口都有范围。
- 每个入口最终回到生命周期。

## 项目知识底座

Project Develop Copilot 内化了项目级 LLM Wiki，把 `.llm-wiki` 作为项目知识索引层。

`.llm-wiki` 不替代源码、PRD、issue、测试或设计文档。它更像一层“项目导航和记忆索引”，帮助 AI 在进入任务时快速知道：当前项目是什么、这次应该看哪里、哪些资料可信、哪些结论已经验证过。

它主要沉淀六类信息：

| 内容 | 作用 |
|---|---|
| 模块边界 | 说明系统有哪些主要模块、职责分别是什么、哪些模块之间有依赖关系。这样可以避免 AI 一上来就全仓库搜索，也能减少改错模块、跨范围修改的问题。 |
| 需求和 Bug 摘要 | 把 PRD、issue、聊天记录、客户反馈等材料整理成可恢复的任务摘要。它不取代原始材料，而是告诉 AI 这次工作的目标、约束和当前状态。 |
| source proxy | 保存外部资料的索引和摘要，例如文档、会议纪要、日志、链接、PDF、需求说明。它的价值是让 AI 知道证据来源在哪里，而不是把聊天里的片段当成事实。 |
| working-context | 记录某一次开发或排障正在使用的范围、假设、已读文件、待确认问题和下一步。它让中断后的继续工作有起点，不需要每次重新解释背景。 |
| 验证记录 | 记录做过哪些测试、检查、构建、人工验证，以及结果是什么。它让交付不是只靠“我改完了”，而是能回看验证依据。 |
| 决策、风险和缺口 | 记录为什么这样做、还有什么风险、哪些信息不完整、哪些问题需要后续补齐。它帮助团队区分“已经确认的结论”和“暂时的假设”。 |

这样做的价值是：AI 不需要每次从零理解项目，也不会把临时聊天内容当成长期事实。对管理层来说，它降低的是上下文丢失、范围漂移、重复沟通和交付不可追溯的风险。

## 管理价值

| 价值 | 体现 |
|---|---|
| 少丢上下文 | 需求、Bug、资料、验证和决策都能回到项目知识层。 |
| 少重复沟通 | 下次继续时先恢复 lifecycle session，而不是重新解释背景。 |
| 降低范围漂移 | 开发前明确 active scope，跨模块扩展需要理由。 |
| 提升交付可信度 | Finish 和 Review 检查验证、wiki、artifact、dashboard 是否一致。 |
| 持续改进团队能力 | Review 发现 project skill 规则缺陷后，可补 acceptance case 和 skill patch。 |

## 边界

Project Develop Copilot 不是万能自动化工具，也不是替代研发流程的黑盒。

它的边界是：

- 不替代源码、测试和用户决策。
- 不默认深读整个 monorepo。
- 不默认使用旧 graph 或生成数据。
- 不把外部 skills 变成生命周期主线。
- 不声称项目初始化后就理解了所有模块细节。

它更像一个“项目研发流程协调器”：把 AI 的能力放进可追踪、可恢复、可 review 的工程闭环里。

## 适合汇报的结论

Project Develop Copilot 的核心价值，是把 AI 从“回答和编码工具”升级为“项目研发协作系统”。

它帮助团队在复杂项目里保持上下文连续、范围可控、交付可验证、经验可沉淀，并通过 review 机制持续改进 project skills 本身。
